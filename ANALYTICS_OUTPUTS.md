# Analytics Outputs Guide

## Overview

This guide provides comprehensive documentation of all metrics, statistics, and analytical outputs generated by the Crypto L2 Orderbook Analyzer. Understanding these outputs is essential for quantitative analysis and trading strategy development.

## Core Metrics

### 1. Spread Metrics

#### Absolute Spread
**Definition**: The difference between the best ask price and best bid price.

```
Spread = Best Ask Price - Best Bid Price
```

**Output Format:**
```json
{
  "spread": 0.50
}
```

**Interpretation:**
- Lower spread = Higher liquidity, lower trading costs
- Higher spread = Lower liquidity, higher trading costs
- Typical values: $0.01 - $10 for major cryptocurrencies
- Spread widening often precedes volatility spikes

**Use Cases:**
- Execution cost estimation
- Liquidity assessment
- Market making strategy optimization

#### Spread Percentage
**Definition**: Spread as a percentage of mid-price.

```
Spread % = (Spread / Mid Price) × 100
```

**Output Format:**
```json
{
  "spreadPercentage": 0.015
}
```

**Interpretation:**
- < 0.01%: Extremely liquid (major pairs on major exchanges)
- 0.01% - 0.05%: Good liquidity
- 0.05% - 0.20%: Moderate liquidity
- > 0.20%: Low liquidity (smaller pairs, off-hours)

**Use Cases:**
- Comparing liquidity across different price levels
- Cross-exchange liquidity comparison
- Time-of-day liquidity analysis

### 2. Price Metrics

#### Mid Price
**Definition**: The midpoint between best bid and best ask.

```
Mid Price = (Best Bid + Best Ask) / 2
```

**Output Format:**
```json
{
  "midPrice": 45250.25
}
```

**Interpretation:**
- Most accurate current "fair value" of the asset
- Used as reference for all other calculations
- Less noisy than last trade price

**Use Cases:**
- Baseline for price impact calculations
- Reference price for limit orders
- Benchmark for execution quality

#### VWAP (Volume Weighted Average Price)

**Definition**: Average price weighted by volume at each level.

```
VWAP = Σ(Price_i × Volume_i) / Σ(Volume_i)
```

**Output Format:**
```json
{
  "vwap": {
    "bid": 45248.75,
    "ask": 45251.80,
    "spread": 3.05
  }
}
```

**Interpretation:**
- **Bid VWAP**: Average price weighted by bid volumes (typical sell execution price)
- **Ask VWAP**: Average price weighted by ask volumes (typical buy execution price)
- **VWAP Spread**: Difference between bid and ask VWAP
- VWAP closer to mid price = More liquidity concentrated at top levels

**Use Cases:**
- Execution benchmarking (compare actual execution to VWAP)
- Estimating realistic execution prices for orders
- Mean-reversion trading signals

### 3. Imbalance Metrics

#### Order Imbalance
**Definition**: Ratio of bid volume to ask volume in top N levels.

```
Imbalance = (Bid Volume - Ask Volume) / (Bid Volume + Ask Volume)
```

**Output Format:**
```json
{
  "imbalance": 0.35
}
```

**Interpretation:**
- Range: [-1, 1]
- Positive (0 to 1): More buy pressure
  - 0 to 0.2: Slight buy pressure
  - 0.2 to 0.5: Moderate buy pressure
  - 0.5 to 1: Strong buy pressure
- Negative (-1 to 0): More sell pressure
  - -0.2 to 0: Slight sell pressure
  - -0.5 to -0.2: Moderate sell pressure
  - -1 to -0.5: Strong sell pressure
- Near zero: Balanced market

**Predictive Power:**
- Studies show positive correlation with future price movement
- Most predictive in 1-30 minute timeframe
- Works best in liquid markets

**Use Cases:**
- Short-term price direction prediction
- Entry timing for momentum trades
- Identifying accumulation/distribution phases

#### Market Skew
**Definition**: Weighted average price skew near the spread.

```
Skew = (Bid Weight - Ask Weight) / (Bid Weight + Ask Weight)
```
Where weights are calculated within 1% of mid price.

**Output Format:**
```json
{
  "skew": 0.12
}
```

**Interpretation:**
- Similar to imbalance but focuses on orders close to mid price
- Positive: Bullish sentiment (more buying interest near current price)
- Negative: Bearish sentiment (more selling interest near current price)
- More sensitive to near-term price action than general imbalance

**Use Cases:**
- Scalping strategies
- High-frequency trading signals
- Market sentiment assessment

#### Order Flow
**Definition**: Imbalance weighted by distance from mid price (top 5 levels).

```
Order Flow = Σ(Bid Volume_i / i) - Σ(Ask Volume_i / i)
             ────────────────────────────────────────
             Σ(Bid Volume_i / i) + Σ(Ask Volume_i / i)
```

**Output Format:**
```json
{
  "orderFlow": 0.08
}
```

**Interpretation:**
- Range: [-1, 1]
- Emphasizes top-of-book more than deeper levels
- Positive: Near-term bullish flow
- Negative: Near-term bearish flow
- More responsive to rapid changes than total imbalance

**Use Cases:**
- Ultra-short-term trading (seconds to minutes)
- Order placement timing
- Quick sentiment shifts detection

### 4. Liquidity Metrics

#### Total Liquidity
**Definition**: Depth-weighted liquidity calculation.

```
Liquidity = Σ(Volume_i × Price_i × e^(-distance_i / mid_price))
```

**Output Format:**
```json
{
  "liquidity": {
    "bid": 2450000.50,
    "ask": 2380000.25,
    "total": 4830000.75,
    "ratio": 0.507
  }
}
```

**Interpretation:**
- **Bid Liquidity**: Total buy-side liquidity (in USD)
- **Ask Liquidity**: Total sell-side liquidity (in USD)
- **Total**: Combined liquidity
- **Ratio**: Bid / Total (0.5 = balanced, >0.5 = more bid liquidity)

**Typical Values:**
- BTC/USD on major exchange: $1M - $10M
- ETH/USD: $500K - $5M
- Alt coins: $10K - $500K

**Use Cases:**
- Position sizing (don't exceed 5-10% of liquidity)
- Market impact estimation
- Comparing exchanges for execution venue

#### Depth Analysis
**Definition**: Volume available at various distance levels from mid price.

**Output Format:**
```json
{
  "depth": {
    "bids": {
      "0.1": 125000.50,
      "0.2": 248000.75,
      "0.5": 580000.25,
      "1.0": 1150000.80,
      "2.0": 2200000.40
    },
    "asks": {
      "0.1": 118000.30,
      "0.2": 235000.60,
      "0.5": 550000.90,
      "1.0": 1100000.50,
      "2.0": 2100000.30
    }
  }
}
```

**Interpretation:**
- Numbers represent cumulative USD value within X% of mid price
- Example: "0.1": 125000 means $125K of bids within 0.1% of mid price
- Deeper depth at each level = More liquidity = Lower price impact

**Use Cases:**
- Estimating slippage for specific order sizes
- Identifying price levels with strong support/resistance
- Comparing market depth across exchanges

#### Liquidity Pressure

**Output Format:**
```json
{
  "pressure": {
    "buy": 850.5,
    "sell": 780.2,
    "ratio": 0.522
  }
}
```

**Interpretation:**
- **Buy Pressure**: Weighted sum of bid volumes (nearer levels weighted higher)
- **Sell Pressure**: Weighted sum of ask volumes
- **Ratio**: Buy / (Buy + Sell)
- Ratio > 0.5: More buy pressure
- Ratio < 0.5: More sell pressure

**Use Cases:**
- Momentum trading signals
- Gauging near-term directional bias
- Entry/exit timing

### 5. Microstructure Metrics

**Output Format:**
```json
{
  "microstructure": {
    "effectiveSpread": 0.50,
    "realizedSpread": 0.25,
    "priceImpact": {
      "buy": 0.15,
      "sell": 0.13,
      "average": 0.14
    },
    "orderConcentration": 125,
    "sizeDistribution": {
      "mean": 0.85,
      "stdDev": 2.34,
      "skewness": 4.52
    },
    "resilience": {
      "level_1": {
        "bid": 12.5,
        "ask": 11.8,
        "ratio": 1.059
      },
      "level_5": {
        "bid": 58.2,
        "ask": 55.1,
        "ratio": 1.056
      }
    }
  }
}
```

**Interpretation:**

**Effective Spread**: Current bid-ask spread
**Realized Spread**: Estimated actual cost after mean reversion (simplified as 50% of effective spread)

**Price Impact**:
- Expected price movement per unit of volume traded
- Higher values = Less liquid = Higher execution costs
- Use for position sizing and execution strategy

**Order Concentration**:
- Number of unique price levels in orderbook
- Higher number = More fragmented liquidity
- Lower number = Concentrated at few levels

**Size Distribution**:
- Mean: Average order size
- StdDev: Variation in order sizes
- Skewness > 0: Many small orders, few large orders (typical)
- Skewness < 0: Unusual (investigate further)

**Resilience**:
- How much volume exists at each depth level
- Higher ratios indicate imbalanced liquidity
- Quick recovery of orders indicates healthy market

**Use Cases:**
- High-frequency trading strategy development
- Market quality assessment
- Detecting market manipulation
- Optimal execution algorithm design

### 6. Large Order Detection

**Output Format:**
```json
{
  "largeOrders": {
    "bids": [
      {
        "price": 45240.00,
        "size": 15.5,
        "zscore": 3.2
      },
      {
        "price": 45235.50,
        "size": 12.8,
        "zscore": 2.8
      }
    ],
    "asks": [
      {
        "price": 45260.00,
        "size": 18.2,
        "zscore": 3.8
      }
    ],
    "threshold": 8.5
  }
}
```

**Interpretation:**
- **Z-score > 2**: Order is >2 standard deviations above mean (unusual)
- **Z-score > 3**: Very large order (potential whale)
- **Threshold**: Size above which orders are considered "large"

**Detection Method:**
```
Z-score = (Order Size - Mean Size) / StdDev Size
Large Order if Z-score > 2.0
```

**Use Cases:**
- Whale watching
- Detecting institutional activity
- Identifying potential support/resistance
- Front-running opportunities (use ethically)

### 7. Support and Resistance Levels

**Output Format:**
```json
{
  "supportResistance": {
    "support": [
      {
        "price": 45240.00,
        "volume": 45.8,
        "strength": 3.66
      },
      {
        "price": 45220.00,
        "volume": 38.2,
        "strength": 3.05
      },
      {
        "price": 45200.00,
        "volume": 32.5,
        "strength": 2.60
      }
    ],
    "resistance": [
      {
        "price": 45260.00,
        "volume": 42.3,
        "strength": 3.58
      },
      {
        "price": 45280.00,
        "volume": 35.7,
        "strength": 3.02
      },
      {
        "price": 45300.00,
        "volume": 28.9,
        "strength": 2.45
      }
    ]
  }
}
```

**Interpretation:**
- **Support**: Price levels with high bid concentration (buying interest)
- **Resistance**: Price levels with high ask concentration (selling interest)
- **Strength**: Volume relative to top-of-book (higher = stronger level)

**Calculation Method:**
- Group orders into 0.1% price buckets
- Sum volume in each bucket
- Rank by total volume
- Return top 3 levels for each side

**Use Cases:**
- Stop-loss placement (below support)
- Take-profit targets (at resistance)
- Breakout trading (price breaks through resistance)
- Range trading (buy at support, sell at resistance)

### Real-Time Streaming

Data is streamed via WebSocket in real-time:

**Socket.IO Events:**
- `orderbook`: Full orderbook snapshot
- `metrics`: Calculated metrics
- `update`: Incremental updates

**Update Frequency:**
- Major exchanges: 50-500ms
- Update on every orderbook change

## API Integration

### REST API Endpoints

```
GET /api/metrics/:exchange/:symbol
- Returns current metrics snapshot

GET /api/history/:exchange/:symbol?start=<timestamp>&end=<timestamp>
- Returns historical metrics

GET /api/orderbook/:exchange/:symbol
- Returns current orderbook state
```

### WebSocket Subscription

```javascript
socket.emit('subscribe', {
  exchange: 'binance',
  symbol: 'BTCUSDT'
});

socket.on('metrics', (data) => {
  // Real-time metrics
});
```

## Data Quality Metrics

**Reliability Indicators:**

- Data staleness

**Quality Checks:**
- Spread reasonableness (not negative, not excessive)
- Volume consistency (no sudden 10x changes)
- Price continuity (no gaps)
